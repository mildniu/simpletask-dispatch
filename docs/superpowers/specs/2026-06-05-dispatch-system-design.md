# 内部点对点派单系统设计

## 目标

做一个公司内部使用的点对点派单系统。用户从员工花名册中选择身份登录，派单人创建任务并指定一名负责人，负责人处理后提交结果，派单人确认完成或退回。

## 范围

- 当前版本使用内建账号作为员工来源，由管理员维护启用/停用和权限。
- `员工花名册.csv` 读取能力已保留，但暂未接入主登录和用户管理流程。
- 使用浏览器界面访问本地服务。
- 使用 `SQLite` 保存任务、流转记录和结果信息。
- 使用账号密码登录；首次进入系统时初始化管理员账号。
- 结果附件保存到本地 `uploads` 目录，数据库保存文件名和路径。

## 技术方案

- 运行环境：Node.js。
- 服务端：Node.js 原生 HTTP 服务。
- 数据库：Node.js 内置 `node:sqlite`。
- 前端：原生 HTML、CSS、JavaScript。
- 不依赖第三方包，避免当前环境无法安装依赖的问题。

## 角色与权限

- 系统管理员、经理、主管、支局长、成员都可以登录。
- 系统管理员可以新增、停用、调整用户角色和重置密码。
- 任务创建人就是派单人。
- 派单人可以创建任务、查看自己派出的任务、确认完成、退回任务。
- 负责人可以查看分配给自己的任务、接单、提交处理结果。
- 系统管理员可以查看全部任务，并可进行状态变更、删除等系统管理操作。
- 经理、主管、支局长、成员只能查看和处理自己发出的任务、自己收到的任务。

## 任务状态

- 待接单：任务已创建，负责人还未接单。
- 处理中：负责人已接单。
- 待确认：负责人已提交处理结果，等待派单人确认。
- 已完成：派单人确认任务完成。
- 已退回：派单人退回，负责人需要重新处理。

## 数据记录

- 任务：标题、内容、优先级、截止时间、派单人、负责人、状态、创建时间、更新时间。
- 处理结果：处理说明、结果附件、提交时间。
- 退回信息：退回原因、退回时间。
- 流转记录：任务、操作人、动作、备注、时间。

## 验证方式

- 启动服务后访问本地页面。
- 确认启用用户能显示为负责人，停用用户不再可选。
- 创建任务后能在负责人任务列表看到。
- 负责人能接单并提交结果。
- 派单人能确认完成或退回。
- 数据能写入 `SQLite`，刷新页面后仍然存在。
- 可运行 `node scripts/smoke-flow.js` 执行本地临时库 API 冒烟验证。
